# 产品约定

Yorw（Your own research workplace，知栖）面向持续阅读一个研究方向的学生和个人研究者，将原文、讨论、笔记和专题认识连接起来。目标是让知识可积累、可核查、可修订；尚无节时或准确率效果承诺。

## 三个空间

| 入口 | 职责 |
| --- | --- |
| Storage | 管理和阅读 PDF、DOCX、DOC、Markdown、TXT，检索当前原文，进行有来源的问答，保存 Markdown 笔记。 |
| Garden | 组织专题目录，编辑 Wiki，从工作区材料生成独立草稿，由用户追加或替换正文并保留修订。 |
| House | 配置聊天与检索服务、检索偏好，查看数据位置并导出已保存内容。 |

全局入口固定为 **Storage / Garden / House**，不替换成通用中文导航名。其他操作使用清楚的中文。

## 工作标签与页面职责

顶部固定两层：品牌与 Storage / Garden / House 模块导航，下方是统一工作标签栏。模块导航进入模块首页并保留已打开标签；工作标签同步所属模块。文献库和专题目录是稳定首页，不作为可关闭的工作标签。

- **Storage**：文献库是首页，左侧可收起文献目录，打开文献创建或激活阅读标签，文献库仍可返回。首页支持按标题、文件名、作者、年份、标签等本地搜索文献；不调用模型。笔记、检索、问答默认在阅读侧栏切换，也可展开为标有所属文献的独立标签；展开和返回复用同一份输入、结果和编辑状态，不同时挂载两套编辑器或轮询任务。引用和原文跳转定位到对应文献的阅读标签和物理页；目标阅读标签不存在时创建，不覆盖其他文献。文献资料和整理文献都是独立标签；整理文献承载元数据编辑，文献资料聚合标签、人工总结、所属专题、相关文献、笔记、检索历史和问答历史；相关文献由用户手动建立，双向显示，标注说明但不自动扩大 AI 范围。导入支持多选，逐文件显示成功、重复或失败；成功后提供可跳过的“整理资料”入口，打开独立整理标签；不强制填写，也不自动请求总结。
- **Garden**：首页不显示侧栏，顶部提供新建、层级/路径视图、展开收起、刷新和本地搜索，下方完整展示专题。专题正文、专题管理、AI 优化、修订历史和关联材料分别是该专题的标签；新建标签全局唯一，管理标签按专题去重。正文页左侧是可收起的共用专题树（搜索、新建、当前项高亮），右侧保留标题、父级路径、紧凑工具栏和编辑器；名称与父级在管理页编辑，不内嵌正文。新建/管理表单在会话内跨标签保留并在关闭时询问，布局不保存表单内容。AI 优化的生成要求、材料范围、状态、可编辑草稿、追加/替换、来源和草稿历史不堆叠在正文下方；修订历史的比较和回退也只在历史标签内。关联材料区分直接关联文献与后代专题汇集文献；同一笔记按 ID 只显示一次，仍归所属文献所有。
- **House**：设置首页提供文献解析与预览、聊天模型、检索、数据与导出四个入口，各自使用稳定设置标签；检索偏好与导出不在同一页面堆叠。
- **问答**：上方是可滚动消息列表，下方是固定输入区；用户问题与模型回答视觉区分，普通回答自然展开，来源和操作位于对应回答之后。用户位于底部时跟随生成，向上阅读时保留位置并提供“回到最新”；首次打开已有对话定位最新消息。Enter 发送、Shift+Enter 换行，输入法组合输入期间不发送。

标签以“页面类型＋实体 ID”唯一，重复打开激活已有标签；新建专题固定使用 `new`，专题管理使用专题 ID。关闭含未保存笔记、正文、新建/管理表单或 AI 草稿的标签前提供保存/创建、放弃或取消；保存失败保持打开。正常退出后恢复标签顺序、激活项、模块首页、侧栏模式/宽度、专题目录和文献目录的收起状态，以及 Garden 层级/路径视图与展开项；旧布局使用默认值。布局只保存页面描述与界面偏好，不保存正文、表单、密钥、聊天输入或任务结果副本；未保存正文仍依赖明确保存和退出保护，没有崩溃恢复。

文献标签、人工总结和关系不替代原文证据。检索历史只保存提交过的问题、短摘录和引用，不保存键盘过程或整篇 PDF；查看历史不调用模型，重新检索才创建新任务。来源失效、文献移除或关系解除时保留历史快照并标明状态，不静默改写已有笔记、Wiki 修订或来源。

Garden 的 AI 优化默认只使用当前专题及子专题关联的材料；只有用户显式选择“全工作区”才扩大范围。范围内没有材料时给出关联材料或切换范围的提示，不静默改为全库；范围在生成后变化时保留草稿但阻止直接采纳。

## 当前产品原则

- 一次输入完成搜索、问答或生成草稿；选材、索引、提示词准备由后台处理。可取消，失败保留已有结果。
- 原文事实、个人观点和模型推断有不同地位。引用必须能回查，存在引用不等于解释正确。
- AI 不静默覆盖正文。草稿与正式 Wiki 分开，保存和回退均创建修订。
- 数据默认本地保存；云端模型按任务接收所需文本。未配置模型时仍可阅读、编辑、导出及进行本地文字匹配。
- SQLite 管理正文与历史，不建立外部 Markdown 双向同步。内容导出不能称为完整备份。
- 先完成可靠的小库工作流，依据真实失败案例决定扩展，不提前引入复杂 Agent 或插件系统。

## 视觉与交互

顶部横向导航、蓝色强调、浅色表面、PDF 阅读优先。原始已选设计稿见[设计参考](design/reference.png)，它是设计历史参考，不代表当前程序截图或新增功能承诺。

现役样式在 `apps/desktop/src/renderer/*.css`：系统字体 Segoe UI / Microsoft YaHei；主题蓝 `#3158C9`、背景 `#F4F6F9`、正文 `#1E293B`、边框 `#DCE2EA`。当前前端使用 CSS 与模块状态对象，没有引入早期规划中的 Tailwind/shadcn、TanStack Query 或 Zustand。

搜索结果以短原文、标题、页码和跳转为主，限制展示长度；不把维度、索引分块或相似度调参作为用户必经操作。错误、加载、取消和保存结果用贴近内容的文字反馈，不能只靠颜色。
