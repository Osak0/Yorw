# 知栖 Yorw MVP 使用指南

适用：Windows x64 · 0.1.0 本机验证版 · 2026-10-25。

## 安装与打开

运行 `Yorw-Setup-0.1.0-x64.exe`，按向导选择安装位置。完成后从桌面或开始菜单打开 Yorw。也可解压完整分发目录，直接运行其中的 `Yorw.exe`；不能只复制这一个 exe，旁边的 resources 等文件同样必需。

安装包包含 Electron 和 Python 后端运行时，不需要另行安装开发工具。本次按用户选择交付本机验证版；没有在另一台无预装 Node/Python 的干净 Windows 机器上验收。包未签名，若系统拦截，请保留具体提示并反馈，不要关闭系统防护。发行目录中的 SHA256SUMS.txt 可用于核对文件完整性。

首次打开显示空文献库是正常状态。升级前退出旧程序；已有资料存放在应用数据目录，实际路径以 House 显示为准。`pnpm dev` 使用独立开发工作区，不能据此判断安装版资料丢失。

## 三个属于知栖的空间

**Storage** 积累材料与阅读过程；**Garden** 培育自己的专题知识；**House** 安放模型连接与本地工作区。这三个名称是正式导航名称。

第一次建议按下面的顺序体验，先用可公开的短论文或附带的自编写样例。样例没有真实研究结论，不能作为模型准确率评估。

### 1. 在 Storage 导入与阅读

点击“导入 PDF”，选择文本 PDF。后台保存受管副本并抽取文字，列表显示状态；相同文件按摘要去重。原始 PDF 不会因从知栖移除文献而删除。未知作者、年份可留空，通过“编辑元数据”人工补充。

点击“打开阅读”，使用上一页/下一页、物理页码和缩放。阅读位置会在页面成功渲染后保存，重新打开恢复页码。此页码包含 PDF 的封面等物理页面，可能与正文印刷页码不同。抽取失败不等于 PDF 不能阅读，但没有可提取文字时不能使用文本 AI 功能。

### 2. 在 House 分别配置模型

聊天预设 DeepSeek，embedding 预设智谱 `embedding-3`；两者的地址、模型名和密钥独立保存，也可填写兼容服务。请在 House 本地输入 API Key、保存配置，再“测试已保存配置”。不要把密钥发到反馈或聊天中。

数据本地保存不等于完全离线：云端连接测试、检索及生成会发送相应文本，可能计费。聊天与 embedding 账户的用量以服务商为准。没有模型配置仍可阅读、编辑笔记与 Wiki、使用本地关键词检索及导出。

### 3. 检索原文、提问与保存笔记

阅读工具栏有“笔记”“检索”“问答”三个直接入口，侧栏可隐藏。笔记使用 Markdown 编辑，点击保存或 Ctrl+S；切换文献/页面时会话草稿保留，关闭前请保存。草稿尚无崩溃恢复功能。

检索默认只在当前文献中查找。关键词在本地运行，不能可靠地用中文匹配英文原文。若要使用语义检索，先在 House 配置 embedding，再在文献检索面板展开“索引状态与重建”，确认发送当前文献已抽取的全部文字分块，构建语义索引。切换模型或重新抽取后可能需要重建。

启用语义查询会发送本次查询。最低余弦相似度可输入 0–1 小数；默认 0.50 未做通用模型校准，跨语言查询可按实际分数调整。关键词命中或语义达到阈值任一成立即展示。候选片段不是答案，余弦值不是事实可信度。

在“问答”输入问题，点击“准备本次证据”，核对片段和物理页，勾选本次发送范围后生成。只发送本次问题与选中证据，不自动发送历史对话。证据不足时换检索条件或调整阈值，不要把有候选当作已经找到答案。点击有效 [S编号] 可跳原文物理页；“回答转笔记”保存独立笔记及引用快照。取消保留部分输出，在途请求仍可能计费；重试需要重新确认发送。

### 4. 在 Garden 整理专题

创建专题，可选择父级、重命名和调整目录。手工 Markdown 正文保存为新修订，历史保留；目录修改与正文保存是两个操作。

展开“材料与 AI 草稿”，选择论文片段、已保存笔记和已完成对话。输入生成要求，预览完整发送材料、其原文证据与已保存专题正文，核对聊天服务后确认生成。未保存的手工正文不会发送，生成也不会覆盖正式正文。

打开完成建议的“比较与处理建议”，查看生成时基础正文、最新已保存正文和原始建议。可以编辑“确认后的正文”，预览并核对来源后勾选确认，采纳为新修订；也可明确拒绝，原始记录保留。用户观点和模型推断不会因为采纳而变为论文事实。

手工正文有未保存内容时不能采纳/回退；旧基线或失效材料不能直接采纳，应基于最新正文重新生成。历史中的“比较并回退此修订”会复制目标正文及来源为新修订，不删除原历史，也不会把失效来源变为有效。

### 5. 在 House 导出已保存内容

选择已保存笔记和 Wiki 当前修订，“创建快照并导出 ZIP”，通过系统对话框保存到工作区和应用数据目录外的位置。取消后可再次保存同一快照；保存新正文后，必须重新创建快照才能包含新版本。

解压后，`manifest.json` 把标题和对象映射到 UUID 文件名；`.md` 保持已保存正文原样，各自的 `.sources.json` / `.sources.md` 保留材料类型、原始证据、版本和导出时来源状态。

**内容导出不是完整备份**：不含 PDF、密钥、模型配置、聊天历史、未采纳建议、未保存草稿或完整修订历史，不提供恢复导入或目录迁移。卸载程序配置为保留应用数据，不应把卸载重装当作清空资料或恢复工具。

## 异常时如何处理

| 现象 | 建议操作 |
| --- | --- |
| 本地服务退出 | 先保留现场和错误码；已保存内容可关闭重开后核对。未保存草稿仍可见时先记录文字，不能承诺服务故障后仍能保存。 |
| 保存失败或版本冲突 | 当前编辑保留；比较最新保存版本后决定，避免连续盲目覆盖。 |
| 密钥不可用 / 鉴权失败 | 在 House 重新输入对应服务密钥并测试；不要提供密钥截图。 |
| 语义服务失败或配置改变 | 检查 House 配置及当前索引，必要时重建；可先使用明确标记的关键词检索。 |
| PDF 加密、无文字或损坏 | 使用可读取的文本副本；当前不提供解密或 OCR。 |
| AI 回答不正确或引用不支持结论 | 回到原文核查，作为内容质量问题记录；有效编号不等于结论正确。 |
| 导出取消或失败 | 不会显示成功；可重试已有快照，或减少选择后重新创建。 |

## 深度体验与反馈

建议用自己的 5–10 篇合法文本论文重复完整流程，覆盖英文双栏、长文及中英文材料；观察查找证据、来源核对和知识整理是否连贯。需要图表/图像才能回答的问题应明确记为当前能力不足。

请按[反馈模板](review-feedback.md)记录可复现的问题和改进建议；优先报告资料丢失、错误覆盖、来源串错与无法启动，再记录检索效果和交互体验。[已知限制](known-limitations.md)列明本版边界。
