## 实现范围

- 新增 `parsing/` 合同、能力表、注册表和内置解析器；`document_blocks` 保存版本化内容块，保留旧 PDF chunk 引用路径。
- `documents.parse_version/parse_status` 与活动 `extraction_version` 分离；成功重解析切换版本并使派生索引失效，失败保留上一可用版本。
- schema 18：016 内容块、017 处理器设置、018 OCR 引擎。
- 导入支持 PDF/DOCX/DOC/MD/TXT；PDF 使用原文阅读器，其他格式使用结构化阅读视图与章节/内容块跳转。
- 检索从活动 `document_blocks` 构建切片；搜索、问答、笔记来源、检索历史、Garden 草稿均携带 `block_id`/`section_path`，PDF 继续携带物理页。
- House 增加处理器配置、Docling/LibreOffice 能力检测、OCR 模式与 OCR 引擎。
- 内容导出在来源快照中增加 `source_format` 和 `page`/`block` 定位；仍不是完整备份。

## 环境与真实解析

- Docling 2.144.0（Docling Core 2.105.0，Python 3.12.13），通过 `uv tool install --python 3.12 "docling[easyocr]"` 安装；Docling 2.x CLI 使用 `convert` 子命令。
- RapidOCR 随 Docling 工具环境存在；另装 `onnxruntime==1.31.1`。EasyOCR 模型由 GitHub 托管，在当前网络下载不完整，故 OCR 使用 RapidOCR。
- Hugging Face 直连和 Xet CAS 不可用；本机验证使用 `HF_ENDPOINT=https://hf-mirror.com` 与 `HF_HUB_DISABLE_XET=1`。
- LibreOffice 26.8.1.1 用于 DOC 转换。
- 扫描 PDF 需要 `--ocr-mode full_page`；默认区域 OCR 在自编写扫描样例上没有产出文字。
