### Yorw v0.2.0：AI 流程改进计划

2026-10-26。用户已确认方案，并进一步授权在新分支持续执行整个计划，全部完成后统一等待 review。以下三个阶段是实现顺序，不再作为逐步等待门槛。

#### 目标与已确认选择

以知识工作为中心，减少常规操作步骤。此次只处理 Garden 草稿生成失败、AI 操作过繁和检索结果质量/展示三个问题，沿用现有技术栈与视觉风格。

- Garden 默认从整个工作区的已保存文献、笔记和 Wiki 自动选材；后续再优化关联与范围选择。
- 草稿可编辑，最终提供追加到当前 Wiki 或替换正文；每次保存生成修订并可回退。
- 文献问答支持当前文献内的连续追问，历史用于理解问题，答案重新寻找原文证据。
- 检索相关性优先，可以接受现有聊天模型对候选再筛选一次。
- 默认开启语义检索，House 提供全局关闭开关；不再逐次确认费用、建索引或调整相似度。

#### 阶段 1：草稿生成恢复

最初在 `feature/draft-generation-recovery` 实现；完整计划继续于 `feature/ai-workflow-simplification`，起点 main `efd9bd2`。

- 问答输出预算 4,096 token，草稿 8,192 token。
- 区分长度截断、内容过滤、服务繁忙、中断及格式异常；只对明确的长度截断自动续写一次。
- 原始来源、基础正文和生成记录保留；续写仍属于同一草稿，不新建建议或自动保存正文。
- 再次截断展示“草稿未完成”。已有输出的历史失败/中断记录可以编辑补全，通过来源和修订校验后保存。
- 本阶段保持现有选材交互，操作步骤简化在阶段 3 交付。无数据库迁移，不替换 v0.1.0 发布附件。

最初的阶段 1 状态及实测证据见[阶段 1 记录](v0.2.0.md#stage-1)。后续按用户新授权直接继续阶段 2、3，最终统一 review。

#### 阶段 2：统一检索

- 共用关键词、向量、RRF、去重和候选筛选流程，保留现有 embedding 接入；先改进段落/句子分段及中文问句处理。
- 关键词和向量各召回最多 40 个候选，融合后最多 20 个进入现有聊天模型筛选；允许无结果。
- 结果最多 5 条，每条原文摘录最多 220 字符、4 行，显示标题、页码和原文跳转入口。
- 新增统一派生索引覆盖文献、笔记和当前 Wiki 修订；自动按需增量准备、复用、失效和取消。
- 新增持久化检索偏好和可查询进度的后台任务，避免长流程卡在现有 20 秒 HTTP 等待内。
- 新索引使用新增迁移，保留旧正文、原始页文本和历史引用。先试跑 5 题再扩至 20 题，真实模型质量单独记录。

#### 阶段 3：一键问答与草稿

- 检索只输入问题并搜索；问答只输入问题并发送；草稿只输入要求并生成。
- main/Python 负责配置版本、密钥、索引、材料快照和提示词准备；前端显示简短进度、取消和结果。
- 问答最多使用当前文献最近 4 轮、6,000 字符对话理解追问，最多 8 条原文证据。
- Garden 自动从全库选择最多 12 条相关材料片段，保留来源类型、版本和原始证据。
- 草稿区直接编辑并选择追加/替换，追加时合并来源并重新编号，避免不同段落的同名引用冲突。
- 保留幂等、修订冲突检查、未保存编辑保护、回退和导出兼容。旧来源快照继续可读。

每阶段独立验证并提供本机可体验版本。只有实际完成并验证的内容才写入交付记录；不将模拟模型的流程验证视为真实文献质量结论。

#### 当前交付

三阶段已实现并完成本机验证，最终 review 包与测试证据见[完整交付记录](v0.2.0.md#completion)。用户选择在最终程序的 House 配置真实服务，再执行 5 题试跑/20 题质量验收；工程流程验证已完成，真实模型质量没有预判通过。当前等待统一 review，不自动提交、合并或发布。

#### 问题与修复

用户截图中的草稿已经生成部分正文，却显示 `OUTPUT_TRUNCATED`。源码检查和受控 SSE 复现确认两个问题：草稿与短问答共用固定 2,048 token 输出上限；所有非 `stop` 的结束原因都被归类为截断。截图本身不能证明服务端实际返回的是哪一种结束原因。

- 问答默认输出预算改为 4,096 token，草稿为 8,192 token；不新增依赖。
- 单独识别长度截断、内容过滤、服务资源不足、服务中断、不支持的工具调用和协议错误，界面提供简短恢复指引。
- 仅长度截断自动续写一次，沿用相同草稿、基础修订、问题与证据；上一段正文作为 assistant 消息发送，保持本轮来源编号。再次截断标记 `partial`，不宣称生成完整。
- 续写前及每次持久化检查任务状态、模型配置和来源版本；取消、改配置、来源删除后不继续创建模型请求。
- 没有新正文的续写标记为空响应；已有正文继续保留。
- 失败、中断、取消及部分完成的草稿，只要保留正文和错误记录，就显示“编辑并补全草稿”。包括旧版留下的 `failed / OUTPUT_TRUNCATED` 记录。
- 人工编辑后仍通过原来的来源编号、来源可用性、基础修订、幂等及事务校验。保存产生新修订，原始生成正文、失败状态和错误原因保留。
- 输出预算、续写次数和安全结束原因保存在建议的 provider JSON 元数据中；无数据库迁移，schema 仍为 9。未保存编辑的崩溃恢复能力未变化。

| 问题 | 当前行为 |

#### 为什么保留 embedding

本轮判断：现有 embedding 接入可以保留，优先解决页级候选过粗、问句分词、手动阈值和交互编排问题。向量用于语义候选，关键词补充准确术语，再由模型筛选；不把任意相似度阈值作为用户判断相关性的职责。

这是有限范围内的工程选择，尚未证明对真实论文优于所有其他方案。[Microsoft 的混合检索说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview)介绍关键词/向量组合与 RRF；[Anthropic 的 Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)提供 BM25、embedding 与 reranking 的参考。Yorw 本轮实现原文分段及候选筛选，**没有实现该文中的逐段 LLM 上下文生成**，也不引用其效果数字作为本项目成绩。

本轮不引入新的 Skill/插件或自主 Agent 框架。已有服务和本地材料足以先实现一次输入的工作流；新增插件不会自动修复 PDF 抽取、图表理解或来源追踪。OCR、布局/表格解析、多模态 PDF 和复杂 Agent 编排继续后置，后续依据真实资料的失败案例再决定。

#### 数据、取消与兼容

- 只追加迁移 010、011，schema 9→11。升级前用既有 SQLite backup 机制备份，保留 PDF、笔记、Wiki、对话及旧引用；旧程序拒绝写新版数据库。
- 统一派生索引可重建，向量按片段/配置版本缓存，并发构建共用锁。来源删除、重新抽取、修改及 Wiki 修订切换使相应缓存失效；失效来源不继续上传为向量材料。
- 任务、request_id 与进度持久化；取消、配置变更和来源变化在各阶段校验。准备任务先发布流式生成对象，再派发调用，交接失败不产生额外模型请求。重启中断不自动重发。
- main 保留固定 IPC 和来源窗口检查，分别读取聊天/embedding 密钥，通过私有请求头交给后端；任务、renderer 和模型正文不保存密钥。
- 旧来源快照和旧 API 保留。旧独立 smoke 模式对应历史界面；当前完整复现使用下述 verify-mvp 入口，它仍兼容 v0.1.0 制品的旧报告协议。
