## 实际实现

- **步骤 7 文献元数据**：`documents.summary_md/summary_source/summary_updated_at` 保存人工总结及来源、更新时间；`document_tags` 保存去空、去重后的标签，标签按大小写不敏感去重但保留首次写法。`PATCH /v1/documents/{id}` 的 `tags`/`summary_md` 为可选字段：省略时保留原值，空列表/空串清除。文献 ID、SHA256 和受管 PDF 路径不因改名或标签变化而改变。文档模型返回标签、总结来源与时间。
- **步骤 8 文献资料与检索历史**：新增 `resource` 工作标签，`GET /v1/documents/{id}/resource` 聚合文献、标签、总结、所属专题、双向相关文献、相同标签文献、笔记摘要、问答摘要和检索历史。`search_history` 在检索任务提交时写入、完成/失败/中断/取消时更新，保存问题、时间、状态、短摘录、物理页和证据引用，不复制 PDF。读取历史按当前提取版本、chunk、页码和引文动态计算 `available`；查看历史不调用模型。支持单条删除和清空，不删除任务、笔记或对话。
- **步骤 9 文献关系**：`document_relations` 每对文献只保存一行（`low_id < high_id`），关系双向可见，说明共享；自关联返回 `RELATION_SELF`，重复添加幂等，反向添加复用同一行，解除同步且不删除资料。相同标签只作为查找辅助，不自动建立关系；相关文献不自动扩大 AI 材料范围。
- **步骤 10 文献—专题关系与笔记归属**：`document_topics` 保存多对多关系，Storage 资料页和 Garden 关联材料页均可添加/解除。专题材料分为直接关联和后代专题汇集，后代按当前目录动态计算；笔记按 ID 去重，正文仍归所属文献。解除关系不删除笔记、PDF 或 Wiki 修订/来源快照；目录移动不需要重写历史。
- **界面与 IPC**：新增 `StorageTool: resource`、`GardenTool: materials`，同步 workspace-tabs、布局合同、preload、main 校验、shared TypeScript 合同和 Python 路由；没有引入新的状态框架。文献资料和关联材料在 1280×720/1440×900 下使用内部滚动，不产生页面横向溢出。

## 数据与边界

- 迁移顺序：012 文献标签/总结，013 检索历史，014 文献关系，015 文献—专题关系。升级前使用 SQLite backup API 备份；schema 11→15 的旧文献、笔记、问答、Wiki 和来源快照保留。
- 检索历史是提交时快照；删除历史不影响任务和已保存内容。重新检索会创建新的 `ai_search` 任务和历史行。
- 关系表不复制 PDF、笔记或问答；资料页和材料页只读取权威记录。
- 内容导出仍只包含已保存笔记和 Wiki 当前修订，不包含文献标签/总结、关系或检索历史。

## 失败与修复记录

- **资料页候选搜索超时**：关联专题后操作仍处于 busy，烟测在“查找文献”按钮禁用时点击，候选列表不出现。改为等待按钮可用后再点击，功能本身未改。
- **布局证据误报**：布局检查的 `wait` 成功时返回 `undefined`，导致 `opened===true` 永远为假，资源/材料视图被判为未打开。改为成功返回 `true` 后，两种视图在目标尺寸通过。
- **资料页底部关系按钮被拉伸**：`.document-tool-body>*` 的 `flex:1` 作用于“打开专题”按钮容器，形成大块空白。为 resource 工具补充 `flex:0 0 auto` 和独立内边距，截图复核通过。
- **打包验证 schema 误报**：`scripts/verify-mvp.ps1` 对 v0.2 报告硬编码 schema 11，随后改为硬编码 15 仍不能证明报告属实。改为从隔离工作区 SQLite 文件头读取 `user_version`（大端 offset 60），与期望值 15 不符时直接失败；重新运行打包完整流程，报告与数据库均为 15。
- **取消与后台异常竞态**：用户取消检索后，后台线程捕获 `CANCELLED` 时仍无条件更新检索历史，把 `cancelled` 覆盖为 `failed`。改为仅在任务状态实际从 queued/running 转换时更新历史；回归 `test_cancelled_search_history_is_not_overwritten_by_a_late_worker`（RED→GREEN）。
- **资料/材料视图跨实体复用（review Critical/Important）**：两个文献资料标签或两个专题材料标签切换时，React 复用同一组件实例，旧文献的元数据编辑器、候选结果或专题搜索结果会带到新实体，可能把元数据或关系写到错误对象。按文献/专题 ID 重新挂载资料与材料视图，并为异步加载增加序列守卫；回归 `--tabs-resource-smoke` 的 `RESOURCE_STATE_LEAK`/`MATERIAL_STATE_LEAK` 检查（RED→GREEN）。
- **移除文献未结束检索历史（review Important）**：`Library.remove` 取消 `ai_search` 任务时没有同步 `search_history`，历史会停留在 running 直到重启。改为在同一事务内把对应历史标为 `cancelled/DOCUMENT_REMOVED`；回归 `test_removing_document_cancels_running_search_history`（RED→GREEN）。
- **同时间戳导致列表顺序不稳定**：完整回归中 `document_topics` 的 `created_at` 相同时按随机 UUID 排序，偶发失败。改为按表 `rowid`（插入顺序）排序，文献—专题列表、专题材料和检索历史使用稳定顺序；回归完整 pytest 通过。
- 既有测试中的 schema 11 断言按新增迁移更新为 15；未通过放松业务断言或删除测试获得通过。
- 以上失败均未通过伪造记录或降低业务断言解决。

## 已知限制

- 本阶段只在本工作分支实现和验证；**未提交、未合并 main、未发布、未构建 NSIS 安装器**。包版本仍为 0.2.0.0；打包目录是本机受限 PATH 检查，不等于独立干净 Windows。

- 真实云模型逐题质量、跨语言召回、服务商兼容性和干净 Windows 安装/恢复仍需单独验证。
