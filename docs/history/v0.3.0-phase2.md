自动整理只对授权之后新导入且就绪的文献执行，现有文献由资料页手动生成。失败/中断任务不因扫描或重启重发，关闭会取消未完成任务；无法撤销已经发出的上游请求。人工字段不被写入或覆盖。AI 输出只校验结构和支持 ID，不宣称已验证陈述真实性。

每批最多 12000 字符、最多 32 批，超过预算明确报错，不以截断首段冒充全文；多批次再汇总。任务提交检查任务、document version、extraction_version、聊天配置和授权版本，旧/取消回调不能激活。旧结果过期后可查看但不参与新检索，新生成失败保留旧结果。AI 标签移除、隐藏结果、忽略专题不会被同版本重新生成恢复。

元数据方案在 House 提供默认关闭的试用开关。原因：下述夹具只能验证工程契约，尚不足以证明真实模型整理质量；未达到真实质量条件前保留原排序。研究记忆仍仅为计划中的设计草案，不开发画像、长期记忆或自主研究助理。

## Review 整改：DOCX 整理响应与资料页布局

用户报告 DOCX 整理返回 INVALID_RESPONSE，并且 AI 卡片与下方资料分属两个布局区域。确认布局根因是 DocumentResourceView 返回并列的 AI 卡片和带 height:100%/overflow:auto 的资料区域，被外层 flex 压缩；现改为一个 document-resource-page 滚动容器，标题、AI 整理、人工资料和专题入口均在同一自然文档流中，卡片无独立纵向滚动区。

旧任务只保存 INVALID_RESPONSE，没有原始响应、字段或失败阶段，无法追溯用户这次响应究竟哪个字段错误，不能把截图当成已确定的 DOCX 解析故障。代码确认模型 JSON 契约只有字段名、格式约束不完整，且 Pydantic 校验和程序异常都被合并成同一码。整改将 Prompt 升至 enrichment-evidence-v2：完整 JSON 示例、类型/长度、非研究材料空字段规则；对 null 文字、文字列表、单个标签/来源编号等可无损转换的形式规范化，再严格校验。来源编号仍必须属于本次真实输入，汇总也仅接受实际传给模型的编号，不采用猜测或原文替代来掩盖错误，不额外发起修复模型调用。

错误区分响应格式、字段结构、不合法来源和处理异常，记录安全字段名及失败阶段；不记录模型原始输出、全文或密钥。旧失败记录不改写，新一次用户手动重试才产生新诊断。前端中文状态和折叠“失败详情”替代直接堆叠原始阶段码。

验证：test_enrichment 定向 20 passed，前端 24 files / 63 passed，类型/构建通过。完整源码/冻结后端回归为 254 passed / 266.67 秒，无跳过，见 `.cache/phase2-review-fix-backend.txt`。新增中文活动决算 DOCX 通过内置导入、返回 null/文字列表的本地模型夹具、自动整理、人工字段保护、确认专题、元数据原文检索与原件高亮；模型仅调用一次。`.cache/phase2-docx-review-fix-20261029/enrichment-smoke.json` 所有断言通过，1280×720 与 1024×768 的整页滚动、无横向溢出通过，已检查两张资料页截图。可复现样例由既有 make-mvp-fixtures.py 的 --enrichment-docx 开关生成，不提交二进制 DOCX。
