## 问题与修复

用户截图中的草稿已经生成部分正文，却显示 `OUTPUT_TRUNCATED`。源码检查和受控 SSE 复现确认两个问题：草稿与短问答共用固定 2,048 token 输出上限；所有非 `stop` 的结束原因都被归类为截断。截图本身不能证明服务端实际返回的是哪一种结束原因。

- 问答默认输出预算改为 4,096 token，草稿为 8,192 token；不新增依赖。
- 单独识别长度截断、内容过滤、服务资源不足、服务中断、不支持的工具调用和协议错误，界面提供简短恢复指引。
- 仅长度截断自动续写一次，沿用相同草稿、基础修订、问题与证据；上一段正文作为 assistant 消息发送，保持本轮来源编号。再次截断标记 `partial`，不宣称生成完整。
- 续写前及每次持久化检查任务状态、模型配置和来源版本；取消、改配置、来源删除后不继续创建模型请求。
- 没有新正文的续写标记为空响应；已有正文继续保留。
- 失败、中断、取消及部分完成的草稿，只要保留正文和错误记录，就显示“编辑并补全草稿”。包括旧版留下的 `failed / OUTPUT_TRUNCATED` 记录。
- 人工编辑后仍通过原来的来源编号、来源可用性、基础修订、幂等及事务校验。保存产生新修订，原始生成正文、失败状态和错误原因保留。
- 输出预算、续写次数和安全结束原因保存在建议的 provider JSON 元数据中；无数据库迁移，schema 仍为 9。未保存编辑的崩溃恢复能力未变化。

本阶段仍使用原有选材与确认界面；计划中的默认语义检索、自动选材、一步发送以及追加/替换操作在后续阶段实施。
