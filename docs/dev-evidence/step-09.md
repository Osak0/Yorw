## 交付与边界

阅读器新增独立“问答”入口和侧栏页签。输入问题（界面最多 1000 字），用已有检索准备证据；可选语义与自定义 0–1 阈值（初始 0.50）。无证据不调用聊天模型；最多选择 8 个分块，用户核查原文、目标聊天服务和配置版本后确认发送本次问题及所选完整文字，可能计费。检索阶段的语义查询独立发送至 embedding 服务。

后端从当前文献按 segment ID 重新读取原文，不接受 renderer 编造的 quote 或页码。聊天请求包含 system 提示和本次 question/evidence JSON，历史只在本地显示，不自动重发，不提供无来源自由聊天。提示区分事实、推断与不确定性，证据不足时说明不足，不执行材料中的指令；这不能保证模型永不幻觉。

兼容 Chat Completions 的 SSE：接收 delta.content，DeepSeek 显式关闭 thinking，输出最多 2048 tokens；不输出 reasoning_content。Python worker 将增量正文写入 SQLite，前端每 500ms 轮询显示，外部 SSE 与本地 IPC/JSON 传输分开。问题、部分回答、状态、服务快照、提示版本和证据快照持久化。错误/取消保留已接收内容；重启时 running 标为 interrupted，不自动续发收费请求。

取消立即停止接受后续结果，不保证撤销已发送的云端请求或费用；阻塞的网络读取最多等待当前 20 秒 socket 超时，另有 180 秒流时长及大小上限。单 worker；其他已提交请求可能等待在途调用结束。重试通过“重试此问”恢复问题，再准备证据、确认发送，创建新记录，保留旧记录。失败不自动重试。

每轮证据编号为 [S1]…[S8]。未知 S 编号使回答失败，不能转笔记；正文原样显示以供排查。有效编号生成跳页按钮，保存物理页而非印刷页码；删除/重新抽取后引用保留快照但禁用跳页。模型不提供可解析引用时显示缺引用提示，不假装回答已经验证；纯文本展示不加载 HTML、图片或链接。

“回答转笔记”仅接受 completed 消息，由后端按实际引用保存正文、问题、原文和来源标识；重复操作复用同一 note_id，不覆盖用户之后的编辑。导入 Notebook 时保留其他未保存草稿。手工改正文不自动更新原始引用快照，界面明确提示。文献移除后历史消息/笔记保留，来源显示失效。

## 复现与回归清单

1. 退出旧程序，打开 release/step9-review/win-unpacked/Yorw.exe（或 pnpm dev）；工作区自动升级，已存论文、笔记和语义索引应继续可用。
2. 在 House 确认聊天与 embedding 配置独立。本地保存 DeepSeek key，勿发送到聊天中。
3. 打开已有文字的 PDF→“问答”→输入问题→“准备本次证据”。英文关键词可本地检索；中文问英文时可开启语义并调整阈值，先核查召回原文。未命中时不应生成。
4. 勾选片段，确认服务地址、模型和发送范围，再“发送并生成回答”。核查正文逐步出现、完成状态、[S编号]、展开证据与真实原文；点击引用跳页，核对物理页。引用存在不代表结论正确。
5. 生成期间取消，确认保留部分文字且不会稍后变为完成。“重试此问”应保留旧轮次，重新检索确认后生成新轮次；错误 key/服务失败不能显示成功或允许转笔记。
6. 完成回答转笔记，确认编辑器包含问题/回答/原始引用，其他草稿不丢失；手工保存后重启，历史及笔记仍在。重复转存应打开原笔记，不重复创建或覆盖编辑。
7. 用测试文献验证重新抽取/移除后来源失效；不可跳失效引用，历史快照仍保留。测试窄屏覆盖面板、Escape 与页面跳转。
8. 后续回归记录连接/生成结果、引用页码、取消/重启/笔记结果和错误码，不记录 key。总体 review 不等于代表性 5–10 篇材料或多语言逐题评估；无依据/图像问题仍需在集成验收中人工核查，不预填准确率。
