## 功能与格式

House 新增“本地数据与内容导出”，显示实际使用的工作区绝对位置、工作区 ID 与 schema 版本。进入 House 自动刷新已保存内容，也可手动刷新；不提供修改位置、迁移或恢复导入功能。

可选择已保存文献笔记（包括关联文献已移除的保留笔记）及 Garden 专题的当前修订，全选或清空选择。创建时在同一数据库锁内读取所选对象的最新已保存正文、版本与来源快照，随后通过系统保存对话框写入 ZIP。未保存编辑、历史修订或未采纳建议不作为当前正文导出。一次 1–500 项，不接受重复/不存在 ID，正文与清单未压缩合计及 ZIP 本身均限制 20 MiB；超限拒绝，不静默截断。

ZIP 格式 yorw-content-export-v1：

| 文件 | 内容 |
| --- | --- |
| README.md | 导出范围、来源规则与备份限制 |
| manifest.json | 创建时间、工作区 ID、对象到文件的映射、笔记版本/Wiki 修订 ID |
| notes/{UUID}.md | UTF-8 的已保存笔记正文，保持原样 |
| wiki/{UUID}.md | UTF-8 的当前已保存 Wiki 正文，保持原样 |
| 每份 .md 对应 .sources.json / .sources.md | 对象元数据、原始来源/材料及证据快照、导出时可用性；来源编号仅在本份正文内有效 |

UUID 文件名避免标题中的路径字符、同名与 Windows 保留名问题；标题在 manifest 与来源清单保留。正文中的 [S编号] 不改写，来源种类仍区分原文、笔记与模型讨论；来源存在不代表事实已被证实。来源清单可能包含未在最终正文使用、但确实提供过的上下文材料，不能全视为正文已引用。

**内容导出不是完整工作区备份**：不含 PDF、密钥、模型配置、聊天历史、未采纳建议、未保存草稿或完整修订历史，不具备恢复导入/迁移能力。来源摘录可能包含用户选择的研究内容，导出前应核对选择。

## 写入与失败规则

GET /v1/workspace 不接受任意路径；main 补充自己当前实际配置的位置。GET /v1/exports/catalog 返回笔记和专题列表；POST /v1/exports 接收 IDs，在 workspace/tmp 写出独立 export-{task_id}.zip，登记 tasks(kind=export, stage=EXPORT_READY)；GET /v1/exports/{task_id}/file 仅返回对应已成功任务的受限文件。

renderer 只提交选择和任务 ID，不接收通用文件路径写接口。main 打开系统保存对话框，解析所选目标父目录的真实位置，拒绝工作区及应用数据目录内的目标，避免覆盖数据库/受管资料/密钥；同目录独占临时文件写完后 rename 发布。取消、超限、路径受保护、下载或写入失败均不报告成功。成功覆盖已有目标由系统对话框明确提示。

取消保存后可以“再次保存这份快照”，内容保持创建时版本；修改选择或正文后需重新创建快照。临时 ZIP 存在当前工作区 tmp，重启后服务端任务及文件仍可读取；House 最近快照按钮为本次会话状态，重启后可重新创建，不承诺导出历史管理或自动备份。

## 用户 review

1. 退出旧程序，打开上述分发程序。在 Garden 完成步骤 12 的采纳/回退，再到 House，核对数据路径及刚保存的笔记、专题是否出现在导出列表。
2. 选择至少一份笔记和一份带来源 Wiki，创建快照；先取消系统保存，确认没有成功提示。再保存同一快照到桌面等工作区以外目录。
3. 解压 ZIP，按 manifest 找到各 UUID 文件；核对 .md 与应用内已保存正文一致，.sources.json/.sources.md 有正确来源、页码、摘录、对象版本及有效/失效状态。未保存编辑不应混入。
4. 保存新正文后，“再次保存这份快照”仍应是旧快照；重新创建快照才包含新版本。检查已移除文献关联的笔记仍可导出并标注失效。
5. 尝试空选择、受保护目录和取消保存，不能伪报成功。反馈操作或解压异常时提供错误码/现象即可，不提供密钥。
