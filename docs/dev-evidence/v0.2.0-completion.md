## 三项问题的处理

| 问题 | 当前行为 |
| --- | --- |
| 草稿生成失败 | 问答与草稿分别使用 4096 / 8192 token 输出预算；区分长度、内容过滤、服务资源不足、网络中断与格式错误。明确长度截断时在同一草稿续写一次，再截断保留为未完成内容；历史失败/中断草稿有正文时可编辑补全，保存仍检查来源与基础修订。 |
| 操作繁琐 | 搜索输入问题并点击搜索；问答输入并发送；Garden 输入要求并生成。后台准备、复用索引、选择材料、整理提示词及调用模型；移除逐次收费确认、人工建索引、手动相似度与证据勾选。House 提供默认开启的全局语义开关。 |
| 整页与无关结果 | 按原始页文本的段落/句子产生最多 800 字符、100 字符重叠的派生片段；BM25 与向量分别召回最多 40 项，RRF 融合、去重后最多 20 项交给现有聊天模型筛选。结果最多 5 条，每条原文摘录最多 220 字符、4 行，有标题/物理页码/跳页入口，不展示模型改写的摘录。 |

文献搜索和问答限定当前 PDF；追问最多使用最近 4 轮、6000 字符对话理解指代，重新检索原文。历史回答不能替代原文证据。Garden 从全工作区已保存文献、笔记和其他 Wiki 检索，最多选 12 条、24000 字符的序列化材料；当前 Wiki 背景最多 20000 字符，原始基线完整保留。草稿可编辑后追加或替换当前 Wiki；追加合并来源并重排 S 编号，保存为新修订，支持比较、回退及内容导出。

## 为什么保留 embedding

本轮判断：现有 embedding 接入可以保留，优先解决页级候选过粗、问句分词、手动阈值和交互编排问题。向量用于语义候选，关键词补充准确术语，再由模型筛选；不把任意相似度阈值作为用户判断相关性的职责。

这是有限范围内的工程选择，尚未证明对真实论文优于所有其他方案。[Microsoft 的混合检索说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview)介绍关键词/向量组合与 RRF；[Anthropic 的 Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)提供 BM25、embedding 与 reranking 的参考。Yorw 本轮实现原文分段及候选筛选，**没有实现该文中的逐段 LLM 上下文生成**，也不引用其效果数字作为本项目成绩。

本轮不引入新的 Skill/插件或自主 Agent 框架。已有服务和本地材料足以先实现一次输入的工作流；新增插件不会自动修复 PDF 抽取、图表理解或来源追踪。OCR、布局/表格解析、多模态 PDF 和复杂 Agent 编排继续后置，后续依据真实资料的失败案例再决定。

## 数据、取消与兼容

- 只追加迁移 010、011，schema 9→11。升级前用既有 SQLite backup 机制备份，保留 PDF、笔记、Wiki、对话及旧引用；旧程序拒绝写新版数据库。
- 统一派生索引可重建，向量按片段/配置版本缓存，并发构建共用锁。来源删除、重新抽取、修改及 Wiki 修订切换使相应缓存失效；失效来源不继续上传为向量材料。
- 任务、request_id 与进度持久化；取消、配置变更和来源变化在各阶段校验。准备任务先发布流式生成对象，再派发调用，交接失败不产生额外模型请求。重启中断不自动重发。
- main 保留固定 IPC 和来源窗口检查，分别读取聊天/embedding 密钥，通过私有请求头交给后端；任务、renderer 和模型正文不保存密钥。
- 旧来源快照和旧 API 保留。旧独立 smoke 模式对应历史界面；当前完整复现使用下述 verify-mvp 入口，它仍兼容 v0.1.0 制品的旧报告协议。
